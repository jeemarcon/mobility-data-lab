# mobility-data-lab

A local urban mobility data lab. The project generates synthetic datasets for clients, vehicles, and rides, and processes them through a medallion pipeline (Bronze → Silver → Gold) using DuckDB.

## Folder structure

```
mobility-data-lab/
├── data/                        # Production CSVs and generated DuckDB file
│   ├── clients.csv
│   ├── vehicles.csv
│   ├── rides.csv
│   └── mobility.duckdb          # generated by the pipeline (not versioned)
├── docs/                        # Per-table quality rules
│   ├── quality_rules_clients.json
│   ├── quality_rules_rides.json
│   └── quality_rules_vehicles.json
├── src/
│   ├── pipeline/                # Medallion pipeline (Bronze → Silver → Gold)
│   │   ├── bronze.py
│   │   ├── silver.py
│   │   ├── gold.py
│   │   └── detect_anomalies.py
│   ├── quality/                 # Quality rule generation and conversion
│   │   ├── generate_quality_rules.py
│   │   └── rules_to_dlt.py
│   ├── dlt_pipelines/           # Generated Delta Live Tables expectations
│   │   ├── clients_expectations.py
│   │   ├── vehicles_expectations.py
│   │   └── rides_expectations.py
│   └── generate_data.py         # Synthetic data generator
├── tests/                       # Test data and scripts
│   ├── data/
│   │   └── rides.csv            # Intentionally dirty rides for pipeline testing
│   └── generate_edge_case_data.py
├── requirements.txt
└── README.md
```

## Input tables

### clients

| Column       | Type   | Description                              |
|--------------|--------|------------------------------------------|
| client_id    | int    | Unique client identifier                 |
| name         | string | Full name (faker pt_BR)                  |
| city         | string | Registration city                        |
| signup_date  | date   | Registration date (up to 2 years ago)    |
| is_active    | bool   | Account status (75% active)              |

### vehicles

| Column     | Type   | Description                             |
|------------|--------|-----------------------------------------|
| vehicle_id | int    | Unique vehicle identifier               |
| type       | string | Type: `car`, `bike`, or `scooter`       |
| plate      | string | License plate (faker pt_BR)             |
| year       | int    | Manufacturing year (2015–2026)          |

### rides

| Column      | Type     | Description                                         |
|-------------|----------|-----------------------------------------------------|
| ride_id     | int      | Unique ride identifier                              |
| client_id   | int      | FK → clients.client_id                              |
| vehicle_id  | int      | FK → vehicles.vehicle_id                            |
| start_time  | datetime | Ride start (last 90 days)                           |
| end_time    | datetime | Ride end (start_time + duration)                    |
| distance_km | float    | Distance in km (0.5–30 km)                         |
| fare        | float    | Fare in BRL (distance × multiplier 1.5–3.0)        |

## Medallion pipeline

All layers are persisted as schemas inside `data/mobility.duckdb`.

### Bronze

Exact copy of the CSVs with no transformation. Preserves every record, including invalid ones.

```
bronze.clients / bronze.vehicles / bronze.rides
```

### Silver

Applies quality rules from the JSON files in `docs/`. Each rule has an `on_violation` field:

| Value  | Behavior |
|--------|----------|
| `drop` | Row removed from silver and recorded in quarantine |
| `warn` | Row stays in silver but also recorded in quarantine |

The `_quarantine` table includes a `violated_rules` column listing each violated rule with its severity prefix (`[drop]` or `[warn]`).

```
silver.clients / silver.clients_quarantine
silver.vehicles / silver.vehicles_quarantine
silver.rides / silver.rides_quarantine
```

### Gold

Aggregated tables built exclusively from silver data.

| Table                        | Description                                              |
|------------------------------|----------------------------------------------------------|
| `gold.revenue_by_client`     | Rides, revenue, avg fare, and avg distance per client    |
| `gold.rides_by_vehicle_type` | Volume, revenue, and avg duration per vehicle type       |

## How to run

### Prerequisites

```bash
pip install -r requirements.txt
```

### 1. Generate synthetic data

```bash
python src/generate_data.py
```

Creates `data/clients.csv`, `data/vehicles.csv`, and `data/rides.csv` with 200 clients, 50 vehicles, and 2,000 rides. To change the volumes, edit `N_CLIENTS`, `N_VEHICLES`, and `N_RIDES` in [src/generate_data.py](src/generate_data.py).

### 2. Generate quality rules (requires Anthropic API key)

```bash
python src/quality/generate_quality_rules.py
```

Reads CSV schemas via DuckDB and uses Claude to propose quality rules, saved to `docs/quality_rules_*.json`.

### 3. Run the pipeline

```bash
python src/pipeline/bronze.py
python src/pipeline/silver.py
python src/pipeline/gold.py
```

All layers are persisted in `data/mobility.duckdb`. To inspect:

```python
import duckdb
con = duckdb.connect("data/mobility.duckdb")
con.execute("SELECT * FROM gold.revenue_by_client LIMIT 10").df()
```

### 4. Run with test data

Append `--test` to load from `tests/data/` into isolated `bronze_test` and `silver_test` schemas, without touching production data:

```bash
python src/pipeline/bronze.py --test
python src/pipeline/silver.py --test
python src/pipeline/detect_anomalies.py --test
```

To regenerate the dirty test data:

```bash
python tests/generate_edge_case_data.py
```

### 5. Convert rules to DLT (optional)

```bash
python src/quality/rules_to_dlt.py
```

Generates `src/dlt_pipelines/*_expectations.py` files ready for use in Delta Live Tables pipelines.
